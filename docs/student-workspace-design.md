母版只读来源：`D:/Development/Anime.js/public/sites/animejs-com-23cc7dc7/documentation-ec29569f/`。项目副本位于 `public/assets/student/`，不依赖母版目录运行。

## 页面结构和原样资源

完整复制 Docs 的 HTML 外壳、顶部搜索、侧栏、预览容器、内容容器、搜索弹层及页脚。`core.css`、`docs.css`、`docs.js`、全部运行依赖及字体保持原始字节；没有新增或覆盖字号、行高、列宽、间距、断点和动画参数。`StudentDocsPage.module.css` 只负责承载整个独立文档，不覆盖文档内的样式。

左栏用原有 `docs-nav-item` 组织六组业务、十五个操作及六个住宿申请子页（提交、记录各三个）；中栏保留母版 Documentation 总导航点阵、六个模块预览、十五个功能预览及六个子页预览，仍由原始运行时负责滚动、激活、播放与折叠；右栏保留 `docs-info-content formatted-text`、标题、说明、模块入口、前后导航及完整页脚。顶部 Logo 换为项目 SVG，账户按钮复用首页和登录页的实现，Docs 返回学生工作台总导航，Learn 保留原站链接。搜索使用母版搜索组件，在学生业务菜单中搜索，支持键盘操作。

六个模块依次采用母版前六种颜色：个人信息为红色、住宿业务为珊瑚橙、缴费管理为橙色、报修服务为黄色、公告查看为柠黄色、个人消息为青柠色。侧栏、预览及搜索结果使用同一份映射。模块标题进入各自总览，模块与子功能的 `data-id` 各自唯一，避免首个功能的选中状态落在模块标题上。子功能列表的第三个 class 保留母版颜色类，满足原搜索组件的主题读取规则；不修改原始 CSS 和 `docs.js`。

侧栏主题映射保留在父级 `li`，链接本身不设置 `data-color`，以继承母版按选中、未选中和悬停状态计算的文字颜色。母版 `[data-color]` 会直接强制主题色，将其放在三级链接上会让未选中项也着色；生成脚本和静态校验共同防止此属性重新出现。浏览器颜色回归检查住宿及报修六组三级目录的切换、刷新、返回、搜索及手机展开状态。

十五个子功能页的主标题上方保留母版 `docs-breadcrumb text-ui` 模块链接，点击返回所属模块总览。HTML 结构直接复制自母版 `documentation--getting-started--installation-d54d2aec/index.html`，只替换模块名称、地址与颜色编号，并移除无关的版本链接；字号、位置、间距和交互样式全部使用现有母版 CSS。初次打开及页面内切换均显示对应模块，总导航和模块总览不显示此链接。

Logo 旁的版本控件在母版核心脚本初始化后移除，初始状态也不显示。学生各页不再提供数据刷新按钮，需要手动更新时使用浏览器刷新；操作成功后的数据同步保持原有逻辑。外层应用不再为学生端强制显示滚动条，由 Docs 文档负责页面滚动，避免右侧出现重复滑轨。

编辑区域不显示“操作已保存”等成功状态文字；成功后更新字段并退出编辑。仅移除代码编辑元素的浏览器默认焦点轮廓，保持原来的背景、圆角、字号和间距。失败和校验提示仍显示在当前字段内。

确认和取消按钮不沿用母版标签的常驻 `is-active` 状态，默认使用未激活颜色，悬停使用母版高亮色。`assets/css/profile-editor.css` 仅为这两个按钮增加按压期间的底部横条，松开即恢复透明，不改写原始 `core.css` 或 `docs.css`。

修改登录密码沿用相同代码块结构和按钮交互。原密码与新密码的确认仅暂存于当前组件；确认新密码时校验三项并统一调用原密码修改接口，成功后撤销会话并直接进入登录页。取消当前项恢复上次确认内容；失败保留当前输入并显示字段内错误。密码不从服务端回读，不提供复制按钮，不写入浏览器存储；编辑时使用 `type="password"`，确认后只显示固定遮罩。专属输入样式仅去掉浏览器边框和背景、继承代码字体及行高，不改动母版代码块布局。

查看账单和在线缴费使用原有 `links-list links-list-boxed` 列表，每个按钮仅显示账期、总金额、账单状态；缴费记录按钮仅显示金额及缴费时间。文字与箭头沿用缴费模块的橙色悬停效果，不增加摘要字段。三个列表不提供记录搜索，保留分页和在线缴费的未缴清筛选，顶部母版功能搜索继续保留。

点击记录进入二级详情，用与查看个人信息一致的 `h3` 和 `pre > code.hljs` 逐项展示，复用原始复制按钮；金额保留数据库十进制字符串，缴费时间按上海时区展示。主标题改为账单详情或缴费记录详情，上方小标题返回对应列表。在线缴费的未缴清账单详情，在母版底部右侧“下一个”位置提供“支付”导航按钮，保留母版的箭头、颜色、字号和间距，不在详情正文中执行支付。

支付子页使用 `/workspace/student/payment/action-2?record={账单ID}&step=pay`，保留页码、Docs 外壳与预览；使用母版 Installation 的标题和代码框展示账期、待缴金额及可输入的支付金额，使用母版控件选择测试结果和确认／取消。小标题和底部“上一个”返回该账单详情；取消不提交请求，成功或测试取消后更新缓存并返回账单详情，失败保留输入供重试。直达、刷新和浏览器前进／后退均定位页面顶部。已缴清账单不显示支付入口，直接打开其支付子页也不显示支付表单。

三个缴费列表及详情在页面挂载时重置 Docs 文档的滚动位置，保留母版顶部留白和固定导航栏。不要对 `.docs-info` 使用 `scrollIntoView`：该容器位于导航栏下方，元素对齐会使整个文档向下偏移。列表进入、打开详情、返回列表和浏览器前后跳转采用相同的文档顶部定位；手动展开支付表单时仍定位到表单。

缴费页面不显示“正在读取…”或加载占位文字，也不会在请求尚未完成时显示“暂无记录”。进入学生工作台时提前并行读取三个列表，悬停或聚焦菜单时提前准备对应列表；同一请求并发读取只发送一次。`StudentFinanceData` 只存在于当前已认证工作台的内存中，账号或会话变化会创建新实例，不使用浏览器持久化存储。列表接口已包含完整明细字段，点击记录可直接展示；短时间内复用结果，超过5秒时在保留已有内容的同时重新验证。鼠标悬停或聚焦记录按钮时同时预取 Next.js 页面。支付完成后清空旧结果、查询最新余额并重载三个列表；读取失败清除旧内容，仍显示真实错误。初次访问且尚无数据时，接口响应前保留原页面结构，无法消除网络本身的等待时间。

报修服务同样将三个原功能页改为两个子页入口，不再混排表单与记录。“提交报修”提供“提交报修申请／提交报修记录”；“查看进度”提供“当前报修进度／报修进度记录”；“服务评价”提供“提交服务评价／服务评价记录”。地址分别为 `/workspace/student/repair/action-1/{submit,records}`、`action-2/{current,records}`、`action-3/{submit,records}`。主页面的“下一个”进入第一个子页，子页“上一个”返回各自主页；六个子页均使用黄色主题及母版三级目录，标题上方保留报修服务和所属功能两个可点击的小标题。

提交报修申请使用母版可编辑代码块，分别编辑报修房间、故障类型、故障描述、联系电话。房间候选来自本人当前有效住宿记录；故障类型和评分候选沿用业务允许值，控件使用已有申请编辑器的暗色样式。确认只保存本项草稿，取消恢复已确认值；编辑期间不能提交，底部右侧统一执行“提交申请”。成功调用原 `POST /repairs` 后直接进入提交报修记录。服务评价先通过导航列表选择本人已完工且尚未评价的工单，选择后展示报修上下文和服务评分、评价内容两个可编辑代码块，底部右侧统一“提交评价”。评价详情强制重新检查当前工单状态，未完工、重复评价及其他学生的工单不能提交；最终仍由原评价接口校验和写入。

报修记录使用母版导航按钮，摘要展示房间、故障类型、状态、提交时间；评价候选展示房间、故障类型、完工时间，评价记录展示房间、评分、评价时间。三个记录列表不提供搜索，保留分页。当前进度查询待初审、待派工、已派工、已接单、维修中、等待配件；进度记录查询已驳回、已完成、已评价。记录详情使用 `?record={工单ID}`，逐项展示原报修资料、最新维修记录及评价；进度详情同时展示处理过程。使用母版 Installation 的 `h3`、`pre > code` 和复制控件，详情“上一个”返回对应列表并保留页码，不显示“下一个”。评价编辑详情则在右侧位置保留提交操作。

学生报修列表接口只在既有本人范围内附带最新维修记录及维修人员姓名，避免对每个列表条目额外查询；其他角色的列表查询不变。处理过程继续使用已有的本人范围历史接口。`StudentRepairData` 复用会话隔离的内存缓存、5秒有效期及并发去重，悬停三级入口时预取列表，列表数据也可用于立即打开详情；报修和评价提交后清空缓存，不展示加载占位或成功状态文字。进入、详情切换、返回及刷新均回到文档顶部，使用同一母版150毫秒渐显。

## 业务与路由

学生工作台总导航地址为 `/workspace/student`，包含六个模块入口，采用各模块对应的母版主题色。学生登录及通用工作台入口默认进入此页；工作台顶部 Docs 使用母版原生切换返回总导航。总导航位于前后导航顺序的最前面，因此“个人信息”模块的“上一个”返回总导航。总导航和所有模块页均不挂载业务表单。

学生原来的十五个页面地址保持不变。六个模块总览使用 `/workspace/student/{模块}`，功能页继续使用 `/workspace/student/{模块}/action-N`。模块总览仅列出本模块的子功能入口；子页显示对应业务内容，底部只保留母版的“上一个／下一个”按钮。前后顺序按照左栏从上到下排列，每组总览后接本组子功能；首尾缺少相邻页面时对应按钮留空。模块定义在 `src/data/student-modules.json`，功能定义在 `src/data/student-docs.json`，总导航定义与完整顺序见 `src/data/student-pages.ts`。

缴费页面详情使用 `/workspace/student/payment/action-N?record={记录ID}`，页码通过 `page` 保留，旧的 `q` 参数不再参与记录查询。详情底部的“上一个”返回各自列表并保留页码；除在线缴费详情的支付入口外，不显示右侧导航。返回列表后恢复原有功能页前后导航。`StudentFinancePage.tsx` 在同一 Docs 文档中切换列表、详情和支付子页，支持直达、刷新和浏览器前进／后退；查询参数不充当权限依据，详情始终由现有 `GET /api/v1/bills/{id}` 或 `GET /api/v1/payments/{id}` 校验本人数据范围。支付继续调用 `POST /api/v1/bills/{id}/pay`，同一次请求重试复用幂等标识。

`WorkspacePage` 完成身份与角色检查后，学生端使用独立 Docs 文档；其他三类角色继续使用原工作台。跨文档消息检查同源和发送窗口，消息只承载允许列表内的页面标识；账号和权限始终由现有认证与后端校验。

首次文档请求由根布局读取 HttpOnly 会话，并使用现有认证服务查询有效身份后初始化 `AuthProvider`，工作台可直接输出首屏，不再等待浏览器额外请求身份，也不显示“正在确认身份”。身份只用于当前请求，首屏采用动态响应、不跨用户缓存；登录退出仍通过服务端 API，返回标签页时重新校验，后台业务接口继续逐次鉴权。数据库暂时不可用时公共页面仍可访问，客户端可重试身份检查。

首页和登录页由持久应用外壳承载；进入工作台时保留当前页面，学生 Docs 在原页面后方加载，收到已校验来源的就绪消息后再显示。其他角色在其工作台首屏提交后显示。首页原有的工作台模块预加载和路由预取仍保留，登录页的母版布局及页面地址不变。浏览器回归通过延迟身份接口和学生 Docs 文档，验证进入过程保留原页面、不出现身份提示或整页重新导航，并检查四种角色的服务端首屏及禁止缓存响应。

服务端提前输出的 Docs iframe 可能先于父页面完成加载；父页面注册消息监听器后主动发送同源连接请求，文档回复就绪状态，避免错过首次加载消息而无法挂载业务内容。`tests/workspace-entry.ts` 延迟父页面脚本，验证这种情况下仍能显示真实学生资料；原有内容渐显及母版资源不改变。

母版运行时原有的 `documentation-archive-map.js` 适配为本项目页面路径映射。原始 `docs.js` 不修改，继续处理侧栏、搜索、历史导航、预览播放、手机端拖动和最小化。页面变化后由 React Portal 将原有 `LiveWorkspace` 业务逻辑挂载到右侧，仅为学生端选择母版的组件 class。表单编辑和详情在右侧原内容区展开，避免使用旧工作台弹层样式。表格较宽时使用母版 `scroll-container scroll-x`，不改变字体和列宽。

右侧切换沿用母版 `DocsInfos.select()` 的 WAAPI 渐入：150 毫秒、`ease: 'out'`、透明度到 1。本地片段可能在母版 75 毫秒渐出完成前返回，适配层在新片段就绪时显式从 0 渐入，避免渐出被快速读取打断后看不到动画。账单列表、详情和支付子页通过同一文档事件触发相同动画；以内容节点和页面标识去重，避免 React 重挂载导致重复渐显。侧栏、预览和原始动画资源不改写。

保持原接口、参数、幂等支付标识、错误处理、分页与刷新行为。个人资料修改、入住/调宿/退宿、报修与评价、部分测试缴费、消息已读仍然真实落库。所有数据写入均调用原同源 API。页脚订阅提交继续拦截，不向第三方发送邮箱；母版广告脚本不加载。
