# 宿管工作台外壳

宿管端采用母版顶部导航及左侧“功能目录＋动画预览”双栏。七组模块均直接使用母版正文：个人中心的代码框、消息通知的正文详情、住宿与报修的审核办理、基础资料与床位的编辑页，以及账单核对的账单／欠费／催缴列表和独立详情。原19个功能地址保持不变；顶部 Docs 返回 `/workspace/dormManager`，模块标题进入本组入口目录。

外壳位于 `public/assets/manager/`，直接引用学生端已复制的母版 `core.css`、`docs.css`、`docs.js` 和原始 chunks，不复制或改写这些资源。页眉沿用 FLIGHT 标志、搜索、上一项／下一项、Docs/Easings/Learn 与账号退出按钮；左侧保留宿管原有7组功能及顺序，使用母版展开目录、选中颜色、动画预览、刷新／最小化控件及手机菜单。预览来自原始 `documentation-demos.html`，仅替换对应标题和主题编号，业务数据仍由右侧原接口提供。

`src/data/manager-pages.ts` 定义宿管入口与预览映射。`scripts/sync-manager-shell.ts` 根据学生外壳、原始示例和宿管元数据生成 index、页面片段、entries 与预览集合；运行 `node node_modules/tsx/dist/cli.mjs scripts/sync-manager-shell.ts` 同步。`bridge.js` 为宿管独立适配层，处理首屏入口、父子文档握手、账号状态及母版150毫秒渐显。共享路径适配器允许当前文档提供自己的路由映射，学生文档继续使用原映射，避免两个角色之间串页。

`ManagerDocsPage` 只接收同源且来自自身 iframe 的消息，并用宿管页面允许列表解析 ID。业务组件仍由父应用持有的认证上下文调用接口。个人中心直接挂载 `DocsWorkspace` 到母版正文，消息通知复用 `StudentAnnouncementPage`，住宿事务挂载 `ManagerAccommodationPage`，基础信息和床位状态共用 `ManagerResourcePage`（床位保留 `ManagerBedsPage` 导出），报修初审挂载 `ManagerRepairPage`，账单核对挂载 `ManagerBillingPage`。当前七组业务均在母版正文中显示，未匹配入口的旧 ShadowRoot 挂载逻辑仅作为备用。首次进入仍沿用应用的原页面遮罩与就绪握手。

宿管和学生 Docs 外壳由 iframe 文档负责滚动，外层页面不保留滚动条或滚动条占位；全局旧工作台的强制滚动规则仅用于维修人员和管理员，避免宿管端出现双滚动条。

`tests/manager-shell.ts` 校验7组目录、19个业务入口及预览、共享资源引用和选中颜色结构；在独立测试库中验证所有目录切换、外壳不重载、搜索、浏览器前后返回、刷新、手机菜单、资料编辑取消与真实保存、账号退出。四角色浏览器回归已适配宿管 iframe；学生母版资源摘要检查继续保留。

个人中心的查看资料页使用母版 Installation 的 `h3`、`pre > code` 和复制控件，展示本人账号、姓名、角色、电话、邮箱；不显示学生专有字段。修改资料页复用学生端姓名／联系电话／邮箱三个可编辑代码块，确认独立保存，取消还原，无成功状态文字。修改密码页复用原密码提前校验、密码遮罩、最小长度及两次输入一致性校验，最终仍调用原改密接口并撤销该账号全部会话。两个编辑器接受主题编号，学生默认红色不变，宿管继承个人中心青柠色；校验与读取失败统一使用母版 WARNING，原密码错误显示在原密码代码框外下方。标题、可点击个人中心面包屑、相邻导航、字号、间距和复制控件直接使用学生端母版代码，无额外样式覆盖。

`tests/manager-personal.ts` 在独立测试库创建专用宿管，覆盖实际本人字段、空值、复制、确认／取消、逐项保存与刷新、姓名及邮箱校验、读取失败 WARNING、原密码提前校验、真实改密和全部会话撤销、新密码重新登录、手机布局与外层无重复滚动条。共用的密码回归可为学生和宿管分别选择工作台文档。

消息通知列表仅显示“标题 · 已读／未读”，点击进入 `?record=` 独立详情，分页通过 `?page=` 保留。详情使用母版标准正文段落、换行、接收时间和已读状态，纯文本渲染；底部上一项返回原列表页，未读消息的右侧下一项位置显示“标为已读”，保存后移除此操作。复用学生端按会话隔离的预读和缓存，目录悬停／键盘聚焦可预读列表，切换详情从顶部按母版150毫秒渐显；空数据用 INFO，读取或保存失败用 WARNING，无搜索栏或成功状态提示。主题编号由宿管个人消息模块继承为绿色，页标题与全部返回链接保持宿管路径。

`tests/manager-notifications.ts` 通过真实报修产生21条专用宿管通知，验证正文安全和分段、已读位置及持久化、分页返回／刷新／前后导航、母版面包屑间距与渐显、手机布局、INFO／WARNING、跨宿管读写拒绝和切换账号后缓存隔离。

住宿事务三个入口改为“姓名 · 学号 · 业务类型 · 原床位 · 新床位 · 审核状态”的母版导航行，保留分页，取消旧搜索表格和弹窗。点击进入 `?record=` 详情，使用 Installation 的标题、代码框和复制控件逐项显示完整资料；仅待审核记录在底部右侧显示“审核与分配”或“审核办理”。办理页通过 `&review=1` 独立访问，采用学生申请页的可编辑代码块和候选框：审核结果、分配床位（退宿或驳回不显示）、审核意见。确认只保存该字段草稿，取消还原；底部左侧返回详情，右侧“提交审核”调用原审核事务，完成后返回已更新详情，无成功状态文字。已办结记录的办理地址只显示 INFO，不再提供提交操作；读取、字段或提交错误用 WARNING。所有页面保留母版色彩、间距、面包屑、顶部定位和150毫秒渐显，数据缓存随账号和会话隔离。

新增只读 `GET /api/v1/applications/:id/beds` 与 `changes/:id/beds`，要求记录的查询与审核权限，且记录尚待审核、需要分床。候选项分页返回，只包含符合学生性别、意向楼栋、可用房间／床位和宿管授权的床位；与最终分配共用条件构造。提交仍走原事务、行锁与最终状态校验，防止候选读取后床位被占用或停用。无数据库迁移或权限范围扩大。

`tests/manager-accommodation.ts` 使用独立数据库真实创建申请，覆盖三种业务通过／驳回、原因必填、确认／取消、手动及自动分床、床位状态变化后的失败恢复、调宿释放与退宿登记、候选分页／性别／房态／授权、跨类型及越权拒绝、记录分页、刷新与浏览器返回、INFO／WARNING、母版间距与渐显、复制和手机布局。

床位总览及状态更新的导航行显示“床位编号 · 楼栋 · 床位状态”，异常校验显示“床位编号 · 异常说明”；均采用母版导航按钮和分页，取消旧表格及搜索。详情通过 `?record=` 展示完整床位、楼栋、房间、性别限制和实际入住状态，沿用母版标题、代码框、复制、面包屑、顶部定位及渐显。详情底部上一项返回各自列表及原分页；仅状态更新详情的右侧显示“更新状态”，进入 `&edit=1`，上一项返回详情，右侧“提交更新”保存。床位号与状态使用学生端样式的铅笔编辑、确认／取消；房间归属遵循既有数据库不可直接更换的约束，只读展示。空记录用 INFO，字段、读取、保存失败及实际异常说明用 WARNING，无成功状态文字。床位号按数据库20字符上限校验，实际入住仍由原数据库约束保护，不通过更改状态制造或删除入住记录。

床位查询补充房间资料和有效入住布尔值，不增加学生姓名或联系方式。异常查询复用相同楼栋权限，在数据库中完整筛选状态不一致或维修停用的床位并分页，替代旧接口“取前100床位后逐项查询”的漏检和多次查询；每个异常床位只返回一条汇总说明。保留旧 `bedId`／`issue` 字段，新增可直达的 `anomalies/:bedId` 详情，无权限的床位和异常均不可访问。床位相关缓存按账号／会话隔离，编辑保存后全部失效以同步总览和异常页。

`tests/manager-beds.ts` 使用专属宿管楼栋和108张床位，覆盖前100名之外的异常、异常分页和恢复、三类导航及独立详情、真实编辑确认／取消／保存与失败重试、房间不可改和跨楼栋拒绝、实际入住一致性、含中文空格标识、INFO／WARNING、复制、焦点无边框、母版间距／渐显、分页返回／刷新和手机布局。


报修初审的待初审工单、上报维修、驳回报修三个入口分别沿用原来的 pending_review、pending_dispatch、rejected 筛选。列表采用“姓名 · 报修房间 · 故障类型 · 工单状态”的母版导航行，保留20条分页，移除旧搜索、表格及弹窗。通过 ?record= 进入独立详情，以 Installation 的标题、代码框和原生复制控件显示完整报修资料、初审结果及处理过程；底部上一项返回原列表页和分页，仅待初审工单的右侧提供“初审工单”。

初审办理地址追加 &review=1，先展示报修人、房间、故障类型与描述，再以可编辑代码块填写审核结果和审核意见。铅笔进入编辑，确认保存字段草稿，取消还原；未编辑按钮保持母版未激活色，无常驻下划线和输入黑边。底部左侧返回工单详情，右侧“提交审核”调用原 repairs/:id/review 事务；通过进入待派工状态，驳回必须填写原因，保存后返回已更新详情，相应工单转入上报／驳回列表。已初审的办理地址仅显示 INFO，避免再次提交；错误用代码框之外的 WARNING，无读取中或成功状态文字。保留楼栋授权、角色权限、状态锁定、学生进度通知和审计，宿管不提供管理员派工操作。

复用按账号及会话隔离的 StudentRecordData 缓存，悬停／键盘聚焦可预读列表，列表数据预热详情，详情与处理过程并行读取；提交后全部失效。右侧沿用母版字体、间距、面包屑空白、顶部定位、150毫秒渐显及手机布局。tests/manager-repairs.ts 使用专用楼栋和学生，在一次性数据库中验证三个列表、详情、历史、真实通过／驳回、草稿取消、原因必填、失败重试、重复初审、楼栋及角色越权、分页刷新返回、INFO／WARNING、复制／渐显／间距和手机布局。


基础信息的学生、房间、床位三个入口采用母版导航行：分别显示“姓名 · 学号 · 学院”“房间编号 · 楼栋 · 房间状态”“床位编号 · 楼栋 · 床位状态”。保留每页20条分页，取消旧搜索、表格和编辑弹窗。详情通过 ?record= 展示完整资料，使用 Installation 标题、代码框和原生复制按钮；底部上一项返回各自列表及分页，右侧“修改信息”进入 &edit=1 独立修改页。修改页上一项返回详情，右侧“提交更新”调用原 PATCH 接口，完成后返回更新后的详情，无成功状态文字。

学生修改页保留原宿管界面的姓名、联系电话、邮箱三项，性别、学院、年级、学号和账号状态只读，不提供密码及账号操作。房间修改页保留所属楼栋、楼层、房型、容量和状态；楼栋候选通过原 buildings 查询分批读取，只显示授权楼栋，状态使用母版风格候选框。床位修改页复用既有 ManagerBedEditor，床位号和状态可编辑，所属房间遵循数据库不可直接修改的约束。字段长度按数据库上限校验，数字只接受有效正整数；原楼层上限、容量不能少于现有床位、有入住不能停用房间、床位状态需与实际入住一致等事务约束继续生效。代码块确认仅保存字段草稿，取消还原；字段及接口失败用块外 WARNING，空记录用 INFO。

基础信息与床位状态共享按账号／会话隔离的 ManagerResourceData，列表预读、详情预热及保存后的缓存失效一致，切换模块可直接看到新状态。母版原始资源保持不变，复用相同颜色、字体、间距、面包屑空白、顶部定位、150毫秒渐显和手机布局。tests/manager-base-data.ts 在一次性数据库中建立独立楼栋、21名实际入住学生及房间／床位，覆盖三类列表分页、详情与复制、编辑确认取消、真实保存及学生账号资料同步、候选授权、数据库约束、跨模块缓存、越权与失败重试、INFO／WARNING和手机布局。


工作台未登录或会话失效时直接跳转登录页，不呈现“需要先登录”的中间页。主动退出则由工作台统一保留返回首页的目标，学生／宿管 Docs 将退出完成通知交给父页面处理，避免清除认证状态时被自动登录跳转抢先处理。四类角色的登录跳转回归同时验证这两类行为。


账单核对的三个入口采用母版导航行：“姓名 · 账期 · 总金额 · 核对状态”“姓名 · 账期 · 待缴金额 · 账单状态”“姓名 · 提醒标题 · 催缴时间 · 已读状态”。保留20条分页，移除旧搜索、表格及原有行内按钮。详情通过 ?record= 显示完整账单或提醒资料，使用 Installation 的标题、代码框、复制控件和标准描述段落；上一项返回各自列表及原分页。账单详情右侧保留“确认核对”，保存后刷新核对状态、人员编号与时间；欠费详情右侧为“发送催缴”，发送后返回欠费名单，实际通知在催缴记录及学生消息中查询。催缴记录为只读，不提供学生的已读操作或无关下一页按钮。

核对及催缴继续调用原 bills/:id/check 与 remind 接口，不提供费用修改或学生支付操作。发送前刷新当前余额，若已缴清则更新详情并移除催缴按钮；请求处理中锁定操作，避免连续点击重复发送。API失败保留原页面并使用 WARNING，空记录使用 INFO，不展示读取中或保存成功文字。催缴记录查询补充学号和账期，明确限制为宿管／管理员访问；宿管继续依照当前入住楼栋权限查询记录，学生仍只通过本人的 notifications 接口查看提醒。无数据库迁移或财务事务变更。

ManagerBillingData 按账号和会话隔离缓存，目录悬停／聚焦预读列表，列表预热详情，核对及催缴后统一失效。沿用母版主题、字体、间距、面包屑空白、顶部定位、150毫秒渐显及手机布局。tests/manager-billing.ts 在一次性数据库中创建独立学生、23张账单和测试支付，验证真实核对、催缴通知、发送前余额刷新、并发点击保护、学生已读同步、三页分页及独立详情、复制／间距／渐显、读取与提交失败、角色及楼栋范围和手机布局。
